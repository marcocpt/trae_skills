# Mutation Gate（写入批准）

只在即将写入项目产物时读取。本文件是"改文件前取得用户写入批准"的唯一属主；各工作流只声明触发点，不复制细则。

**写入批准（下称 GO）只授权 GO 范围内的文件修改，不替代内容裁决、行为变更裁决与 `delivery_authorization`。**

适用：`bug-fix`、`feature-development`，以及纯文档/文本修改的轻量路径。速通流程（`bug-fast-track`／`feature-fast-track`）见 §5。

## 1. 触发点

- **第一次写入项目产物**（代码、测试、规格、项目文档，含复现测试与对既存文档的改写）时触发。
- 不需要 GO：只读调查、复现命令、日志扫描、工作流内部状态与证据文件、共享持久任务入口（`docs/agent-tasks/*/entry.md`）、`debug-logs/`。
- 草稿例外：本轮**新建、尚未通过其批准 Gate** 的规格/计划（Requirements／Design／mini-spec／任务包／`plan-phase-*.md`）不需要预先 GO，由其批准 Gate 处理；修改既存项目文档仍需 GO。

## 2. GO 必须说清三件事

1. **改哪些文件**——路径或路径模式；模块名、"相关文件"这类表述不算；
2. **每个文件改成什么**——要点即可，不贴全文；
3. **影响与不碰什么**——预期行为变化、回归面、显式排除项。

输出一次即可，不要求用户逐文件确认。

## 3. 复用与失效

- 任务包 `write_scope`（字段属主：[artifact-source-and-packet](artifact-source-and-packet.md)）已明确列出可创建／修改／删除的路径或路径模式，且未超出已批准规格/任务包声明的范围时，该范围即 GO 范围；把依据记入 `decisions`（轻量路径在回复里说明，见 §6）。
- 一次 GO 只覆盖 GO 清单内**已列出**的文件与文件类别；根因确认后触及未列文件，重新 GO。
- 范围扩大、新增文件类别、行为变化，或发现要改用户未批准的行为 → 重新 GO（速通见 §5）。
- 用户明确"按你的判断直接改、风险我担"**并指明范围** → 视为该范围内的 GO，并记入 `decisions`；不可逆操作与高风险决策仍需确认。

## 4. 与 Intake 复述的关系

- Intake 复述解决"理解得对不对"，可以不等确认直接继续调查；
- 本闸门解决"能不能落盘改文件"，必须在第一次写入前取得 GO；
- 两者不合并：**复述通过不等于 GO**。

## 5. 速通与其他工作流

- `bfix`／`fft`：唯一一次复述确认即写入授权，**不适用 §2 的三项格式，也不增加第二次询问**；唯一询问点与覆盖内容由 [fast-track-contract](fast-track-contract.md) §3.1 唯一拥有。速通中发现要动复述范围外的文件时，**不追加 GO**：在本流程已确认范围内继续，范围外部分记入欠账台账留到补齐阶段，或按 fast-track §3.2 第 2 类记 `not-authorized` 停在动作边界，不在速通阶段写入。
- 已被其 `SKILL.md` 明确指向本文件的其余工作流：仅当该 Stage Gate 的批准**明确列出写入范围**（路径或路径模式）时等价于 GO；只写"批准需求／方案"不算，仍需一次 GO。

## 6. 轻量文档路径

适用于**不改变规范语义**的文本/文档修改（措辞、笔误、格式、局部说明、不改变判定口径的用例数据）。需要产出或改变规范语义的规格文档仍走 `spec`。

不建 worktree、不写工作流状态、不跑 CI；复用依据在回复里一句话说明，不写 `decisions`。但仍须：

1. 一句话复述范围（改什么、不改什么）；
2. 按 §2 输出 GO 三件事；
3. 取得 GO 后再修改。

单文件、单处措辞且用户已指明位置与改法时，GO 可压缩为一行："我把 `<文件>` 的第 N 段从 A 改成 B，可以吗"。

## 7. 红线

- 未取得 GO 就写入项目产物（含复现测试、文档）；
- 用"用户催得急""改动很简单"推断免 GO；
- 在 GO 范围外顺手改（夹带）；
- 无依据声称已获 GO，或把"用户没反对"当成 GO；
- 把 GO 当成内容批准、行为变更裁决或 Git／外部动作授权。
