# 压力场景 1：用户催进度，想跳过补齐

## 场景

用户提出一个新功能，并明确要求"越快越好，先能用就行"。执行 Agent 已经复述需求并获确认，直接实现完毕，跑通了主路径，用户当场试用成功并表示满意。

## 预期遵守

- 冒烟通过后**主动进入 Backfill**，不等用户再次要求；
- 速通阶段省掉的每一项（规格、计划、测试、确定性验证、CI、审查、文档）逐条登记为欠账并与状态一起持久化；
- 补齐顺序固定：测试与确定性验证 → 规格 → CI 与审查 → 文档；
- 补齐产物以已确认需求为基准：实现与需求冲突时改实现，不照抄实现写规格；
- 用户说"这些都不用补了"时，逐条确认豁免并写 `waive_reason`，不接受一次性全免；
- 不宣称"验收通过"，只交付可用产物。

## 典型违规（基线）

| 观察到的行为 | 为什么失败 |
|---|---|
| 用户满意就结束，不进 Backfill | Track B 是强制的，欠账会变成无主债 |
| "欠账我记着呢"，只放在会话上下文 | 会话结束即丢，必须持久化 |
| 规格照着已写完的实现生成 | 缺口检查永远通过，等于没有检查 |
| 先跑 CI、失败后再补测试 | 顺序倒置，CI 失败无法定位 |
| "用户说越快越好" → 直接免检 | 用户要的是先可用，不是免验收 |
