# ChatGPT 文件 Grilling 审核

## 目标

角色反转的审核闭环：**ChatGPT 是主审**（经只读通道自行读取指定文件，找问题、给意见），**本地 agent 是执行者与核对者**（逐条核对意见、执行获批修改、送回复审），**用户是最终裁决人**。每次只处理一个风险点。

## 角色分工

| 角色 | 职责 | 禁止 |
|---|---|---|
| ChatGPT（主审） | 用其可用工具读取指定文件，输出结构化风险点与修改建议 | — |
| 本地 agent（执行+核对） | 送审、逐条核对 ChatGPT 引用、执行获批修改、送复审 | 不得机械接受意见；不得未经裁决修改 |
| 用户（裁决人） | 对每个风险点裁决：TODO / LATER / 立即修复 / 不采纳 | — |

**违反规则的字面意思就是违反规则的精神。**

## 输入

开始前必须确认（缺失则向用户提问，不得猜测）：

1. **仓库名**：按技能 gpt-review-loop 的命名规则（`cpdf` / `cpdf-wt/<分组>/<分支名>` / `work/<相对路径>`）；送审前 `git worktree list` 确认存在
2. **文件清单**：用户指定的待审文件（仓库内相对路径）；用户只给了目录或分支时，先送审"列范围"请求，拿到 ChatGPT 发现的文件清单后与用户确认
3. **可选权威依据**：需求/设计/规范文档路径（有则一并在送审内容中指明，让 ChatGPT 对照）

## 循环状态机

1. 确认输入（仓库名 + 文件清单）
2. 首次送审（见「首次送审模板」），拿到 ChatGPT 的风险点清单
3. **本地核对**：对 ChatGPT 引用的每个文件、行号、结论，用 Read/Grep 当场验证；引用有误的明确标注（不得机械接受）
4. 选出最高优先级的**一个**风险点，展示：ChatGPT 意见 + 本地核对结论（格式见「风险点展示格式」）
5. 提出裁决问题（见「裁决提问要求」），等待用户
6. 执行裁决；若为「立即修复」，修改后走「修复后强制复审」直到 ChatGPT 满意
7. 还有未处理风险点 → 回步骤 4；没有 → 询问用户是否扩大范围/收尾（不得自动继续）

<HARD-GATE>
- 每轮只处理一个风险点、只提一个裁决问题；用户未回答不得继续下一个
- 不得提前列出"后面还有哪些问题"，不得一次给出全部清单让用户批量决定
- ChatGPT 一次返回多个问题时，本地按优先级排队，仍然逐条走裁决
</HARD-GATE>

## 首次送审模板

调用契约（conversation_id、timeout 600、轮询、断线重连）遵循技能 gpt-review-loop。content：

```
请使用你可用的工具，自行读取仓库 "<repo>" 中的以下文件（不要依赖我提供内容）：
<文件清单，每行一个相对路径>

逐文件审核：正确性、边界处理、错误传播、与同目录其他代码的一致性；
如有提供需求/设计文档（<文档路径>），同时审核实现与文档的一致性。

输出结构化风险点列表，每条含：优先级（高/中/低）、问题描述、位置（文件:行号）、修改建议。
如果无法读取任何指定文件，直接回复一行：无法读取指定文件。
```

## 修复后复审模板（同 conversation_id 续发）

```
我已按你的第 <N> 条意见修改，请重新读取以下文件复审：
<被修改的文件清单>
修改说明：<每个文件改了什么、依据哪条意见>
请明确回答：满意，或不满意 + 具体问题清单。
```

复审规则：

- 「有条件满意」不算满意：未决项必须显式处理（采纳修复 / 说明立场 / 登记待用户裁决）后再送审
- 迭代直到 ChatGPT 明确回复「满意」，才可标记该风险点闭环
- ChatGPT 复审新发现的问题：回到状态机步骤 3，作为新风险点走裁决（不得擅自直接修）

## 风险点展示格式（MUST）

展示任何风险点时，必须给出相关方法的**完整源码**，问题语句用 `// ⚠️` 标注在**上方独立注释行**；代码块后只补 1-3 条要点。禁止：把代码打散配大段文字、行尾长注释、用宽表格替代代码。

展示内容固定四段：**ChatGPT 意见**（含其给出的优先级与建议）→ **本地核对结论**（引用属实/有误，逐条）→ **合并后的风险判断** → **建议处置**。

## 裁决提问要求

- 只含当前一个风险点；2-4 个互斥选项编号；标推荐项；每项一句影响说明
- 推荐项不固定：修复导致错误结论且任务允许改 → 推荐立即修复；只读审核任务 → 推荐 TODO；低优先级 → 推荐 LATER
- 用户回答含糊 → 重新提问，不得猜测裁决
- 选项：`加入 TODO` / `加入 LATER` / `立即修复` / `不采纳`（不采纳时记录理由，不强制追问）

## 修改边界

- 未经用户裁决，不得修改任何文件；不得顺手修复相邻问题
- 执行获批修改时：只改当前获批事项，不夹带重构；改后重新读取文件核对；说明修改位置和结果
- TODO 项不得立即改；LATER 项不得继续当阻塞项

## 基线失败（无本技能时的真实错误）

| 真实失败 | 技能对策 |
|---|---|
| 机械接受 ChatGPT 意见（行号/引用错误也被照单执行） | 步骤 3 强制本地核对，引用有误必须标注 |
| 一次倒出全部问题，用户无法裁决、修改互相打架 | HARD-GATE 一次一个风险点 |
| 改完不复审就宣称闭环 | 修复后强制复审，满意前不得闭环 |
| 送审不指定文件清单，审核漂移或干等粘贴 | 输入必须含文件清单 + 首次送审模板 |
| 修改时夹带无关重构 | 修改边界：只改获批事项 |

## 红线 - 出现即停下纠正

| 借口 | 现实 |
|---|---|
| "ChatGPT 说的肯定对，直接照改" | 引用可能错；先本地核对，再走裁决 |
| "问题都差不多，一起问了效率高" | 一次一个风险点是硬门禁 |
| "修改 obvious 不用等裁决" | 未经裁决不得改任何文件 |
| "复审太慢，改得对就行" | 满意前不得闭环，这是流程契约 |
| "顺手把旁边的问题也修了" | 夹带 = 边界失控，新问题走新裁决 |

## 禁止事项

- 一次列出全部风险点；一个提问捆绑多个裁决
- 未核对 ChatGPT 引用就展示或执行其意见
- 未指定文件清单就送审；把代码粘贴进 content（ChatGPT 自行读取）
- 修改后不送复审就宣称风险点闭环；「有条件满意」当作满意
- 复审发现的新问题不经过裁决直接修
- 复审 content 提及通道/工具实现机制（保持业务视角）
