## 1. 用户问题和业务目标

在 writing-design-specs/SKILL.md 步骤 3 审查维度中加入"docs.md 合规性检查",形成"步骤 0 读规则 → 步骤 2 写规范引用规则 → 步骤 3 验证规则合规性"闭环。

当前 3 个审查维度(完整性+一致性、可计划性+范围+YAGNI、可验证性+UI可观测性)均未验证目标文档是否符合 docs.md 规则,导致步骤 0 读取的规则在产出阶段无人验证。

## 2. 成功标准

- 步骤 3 审查时,审查员 A 必须检查目标文档是否符合 docs.md(或默认规则)提取的 6 项规则
- 审查报告中标注"规则基准来源"(docs.md 路径 或 "默认规则")
- 三类目标文档(设计规范/视觉原型/测试用例表)审查维度均含 docs.md 合规性
