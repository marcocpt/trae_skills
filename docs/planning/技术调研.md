# 面向人类审核与弱模型执行的精简文档体系

> 最后更新：2026-08-27 | 版本：v0.2 | 状态：已实施，效果待评测

## 决策摘要

保留两个 writer：dd-project-docs 管项目级长期约束，dd-writing-specs 管单次变更规格。已按“单一事实源＋按需视图”实施 R1–R4 与 D1–D7：统一共享合同，补原文反查、授权分离和四层证据，并用弱模型做红绿复测。改动仅在隔离 worktree，未 Git 交付；端到端 token／质量收益仍待对照评测，不评选未经实测的“整体最佳”。

## 建议

目标是在不降低约束遵守率和验收质量的前提下，减少阅读、生成、审查与返工的总成本。以下区分“已读来源事实”和“本地拟议变更”；登记不等于批准。

### 两个 writer 的边界

| 现有入口 | 唯一职责 | 不应承担 |
|---|---|---|
| [dd-project-docs](../../dd-project-docs/SKILL.md) | Research、项目路线图、架构合同、编码规范、AI 约定、阶段合同等项目级文档 | 重写功能 AC 或逐任务实现计划 |
| [dd-writing-specs](../../dd-writing-specs/SKILL.md) | 单次变更的 Requirements、Design、Visual、Test Matrix | 复制项目合同或拥有共享运行规则 |

建议保留职责拆分，共享规则下沉 Runtime；Feature 消费两层事实并组织实现。两个 writer 并非“人用／模型用”的划分，也不意味着同一需求写两遍。现有[精简迁移约束](../migrations/2026-08-23-skill-consolidation.md)已要求下游只拥有增量事实，应延续而非另建体系。

## 候选对比

以下“借鉴、不采纳、归属、验证”均为本地建议，验证方式尚未执行。来源内容已按末节版本读取；这里只对机制适配性作判断，不比较未经实测的模型能力、速度或社区排名。

| 来源 | 解决的问题 | 借鉴点 | 不采纳部分／适配边界 | 现有归属 | 验证方式（后续） |
|---|---|---|---|---|---|
| [agent-docs][s1-agent]／[refresh-repo-docs][s1-refresh] | 入口过长、全量重读、文档漂移 | 小入口、按需加载；用断链、结构或时间变化定位检查范围 | 漂移信号不是错误结论；不能把批准需求改成当前代码行为；不照搬绝对行数限制 | 两个 writer 的路由与既有文档维护入口 | 注入断链、结构变化及“代码违反需求”三类样例，检查是否准确定位且不改规范事实 |
| [decompose-spec][s1-decompose] | 大任务撑满上下文，碎任务产生隐式耦合 | 按上下文与耦合拆分；共享决策唯一属主，依赖显式化 | 不引入 build ledger、PR 链或新编排器；不把固定上下文比例当通用阈值 | Feature 的阶段规划与 [planning](../../dd-feature-development-workflow/references/planning.md) | 用共享接口的跨模块任务，检查无循环依赖、重复属主和未说明的前置条件 |
| [doc-coauthoring][s2-doc] | 作者理解、无历史上下文的读者却无法执行 | 冷读测试：仅凭材料回答目的、下一步、通过与停止条件 | 不照搬大量逐节问答；许可待核验，不直接复制文本 | writer 自检与既有审查 Gate | 给未参与写作的读者同一材料，记录歧义和需追问次数 |
| [Spec Kit analyze][s3-analyze] | 规格、计划、任务间的重复、歧义、冲突与遗漏 | 只读交叉检查；发现无需求归属的任务与无任务覆盖的需求 | 属于命令模板；不引入平行的 `.specify` 规格体系，关键词匹配不等于语义证明 | Runtime 审查规则及 Specs／Planning Gate | 注入重复规则、矛盾约束、遗漏 AC 和游离任务，核对发现与误报 |
| [OpenSpec propose][s4-propose] | 产物顺序隐含、写作规则被复制进正文 | 显式产物依赖；从磁盘重读依赖，规则作为输入而非输出内容 | 不引入 CLI／平行状态；文件存在不等于批准，[verify 的启发式核对][s4-verify]不等于测试运行通过 | writer 上游检查与现有 Stage Gate | 放入未批准／已过期的依赖及失败测试，确认仍阻止下游 |
| [Superpowers writing-plans][s5-plans] | 执行任务缺输入接口、输出接口和验证步骤 | 明确 Consumes／Produces、文件范围、验证命令与预期 | 本地已继承部分机制，只补增量；不整套重引入，也不把完整实现抄进每层合同 | Feature planning 与派生执行包 | 用零历史上下文执行一个任务，检查接口、测试判据及失败处理是否自足 |

最初参考的 [implement-spec][s1-implement]主要是实现与验证流程，而非另一种文档 writer；借鉴点见 R1、R4。不采用其默认自主提交／推送／PR 路径，亦不因省 token 关闭质量检查。SteveVitali 仓库的 [README][s1-readme]说明了面向较强模型的使用背景，不能据此认定弱模型同样有效。

## 文档约束

以下约束已接入现有体系；实际收益仍须按后文方案评测。

| 编号 | 拟议约束 | 接入现有体系 |
|---|---|---|
| D1 | 唯一事实源：每条规范事实只有一个属主，以稳定 ID 引用。项目合同拥有跨功能边界；功能 Requirements 拥有本次 AC，Design 只写增量设计，Test Matrix 拥有本次验证策略。 | Project Docs／Specs；项目级测试规则由既有规范拥有，Matrix 引用而不重定义 |
| D2 | 人审视图只呈现改什么、为什么、不改什么、主要风险、待裁决项及依据，不产生新规范事实。 | 原文首页摘要或现有审查记录，不默认增建独立文档 |
| D3 | 弱模型执行包按任务派生：列来源版本与指纹、必要约束、输入／输出接口、允许修改范围、依赖顺序、精确验证命令、通过条件与阻塞处理。 | Feature planning 派生产物，不成为第三套规格 |
| D4 | 执行包自足：仅展开当前任务相关约束一次；关键失败路径、跨模块约束和权限边界不能靠模型跨多份文件拼接。 | 组包方负责追溯上游，执行方按包执行；上下文装不下时按耦合拆任务，不静默截断 |
| D5 | 派生材料不得独立维护：携带全部依赖来源的版本、内容指纹和批准依据；任一依赖改变即失效，重新生成并检查后才能使用。 | 复用现有 artifact／Gate；来源仅“文件存在”或只有旧摘要不算有效 |
| D6 | 按复杂度增减材料：删重复解释，不删失败路径、AC、授权边界；不以字数或 token 上限压掉必要约束。 | 小任务短包，跨模块任务增加依赖／集成检查；不取消当前强制拆分规则 |
| D7 | 动态状态不混入合同正文：进度、执行结果和审查发现写既有状态／证据记录，证据绑定对应版本。 | Runtime 与 Feature 的既有记录；不新增状态系统 |

D4 的展开是带来源的派生副本，不是第二个可编辑事实源。D5 拟优先复用现有版本／指纹机制；本次不编写生成器，也不假定自动失效检查已经实现。修正规范必须回到属主并重新批准，不能直接改执行包。

### 执行包示例：只读核对共享审查归类

本例用真实仓库文件展示 D3–D5，不是代码原型。代码实现任务还须填写实际写入范围和测试命令，不能用本例的文档检查替代测试。

| 字段 | 本例内容 |
|---|---|
| 任务／输入 | T-review-map：核对 R2 的来源事实；读取下列两个原始文件，输出一条带定位依据的差异报告 |
| 来源版本 | 本地基线 `c317d39cb8dd1c76b9fa01aed4377831a9e585cc`；本例不把该版本标为需求已批准 |
| 来源与内容指纹 | `dd-workflow-runtime/references/review-gate.md` → Git blob `176f96fa8279eb23f1eb1ed7599dd14e936ba6ad`；`dd-writing-specs/references/review-and-delivery.md` → Git blob `ecd8dd9b476c912a89d07b2b05ac891c4493d6d0` |
| 必要约束 | 只读两个来源；必须核对原文而非仅信 R2。差异是候选修订依据，不得自行裁决或改写规则 |
| 范围／输出 | 允许修改范围为空；仅输出 `结论、文件与行号、下一安全动作`，不提交、不安装、不启动实现 |

执行顺序（工作目录为仓库根目录）：

1. 运行下方命令，逐项核对两个输出与表中指纹。缺文件、命令失败或指纹不符即 `BLOCKED`，请求更新来源和执行包，不继续使用旧包。

   ```sh
   git hash-object dd-workflow-runtime/references/review-gate.md dd-writing-specs/references/review-and-delivery.md
   ```

2. 指纹一致后，读取完整原文，核对通用 A/B/C 含义，再定位相关表行；命令只提供材料，不自动判定语义通过。

   ```sh
   nl -ba dd-workflow-runtime/references/review-gate.md
   nl -ba dd-writing-specs/references/review-and-delivery.md
   ```

3. 输出可由原文复核的差异及下一步“提交 R2 供裁决”。通过条件是来源匹配、差异有原文行号、无文件写入；发现差异不等于授权修复。若被要求进入修订而未获授权，停止在裁决点。来源缺失时不得猜测或把核对标为通过。

## 验证与风险

### 文档交付检查

检查 R1–R4 状态、候选事实与本地建议边界、来源／ID／引用、共享规则唯一属主、摘要可判定性，以及示例的下一步／通过／停止条件。实施与复测结果见[自检记录](技术调研_审查结果.md)。

### 后续评测方案（本次未执行）

1. 覆盖普通功能、跨模块依赖、上游版本变化、验证失败和缺少授权五类场景。先冻结正确答案、AC 与不可违反的约束。
2. 同一模型版本、任务、代码基线、工具权限与预算，对比现有材料和精简材料；每次使用独立上下文，多轮记录差异，不能只展示成功样例。
3. 同时统计约束违规、AC 遗漏、返工次数及端到端 token；成本包含材料生成、模型执行、审查、修复与失效重生成。人工审核可记录判断耗时和追问次数。
4. 只有质量未退步且总成本下降，才认定精简有效；越权或错误通过一票否决。文本更短、文件更少或一次示例成功均不算通过。正式评测前还需确定样本量与可接受波动。

### 可行性与风险

接入点已有 writer、Runtime 和 Feature references；可先用人工派生的小样本评测，不以新增工具为前提。尚未测量维护工时、跨宿主执行差异或模型收益。

| 等级／风险 | 影响 | 拟议控制 |
|---|---|---|
| 高：压缩漏掉 AC、失败路径或跨功能约束 | 错误实现仍被判完成 | R1 原文反查＋D4 自足检查，缺事实即阻塞 |
| 高：派生包或证据过期；存在被当成批准／通过 | 按旧合同执行或虚报结果 | D5 校验所有来源；R4 分开覆盖与执行结果，失败不得降级为通过 |
| 高：外部流程默认越权写入或交付 | 未批准改规范、提交或触发外部动作 | R3 单独核验批准与动作授权；只借鉴机制，不运行外部工作流 |
| 中：许可不明 | 后续直接复制缺乏明确许可依据 | Anthropic 该项暂不复制；其他项若复制或改编，先核对适用许可并保留要求的声明 |
| 中：过度拆分、反复派生或宿主工具差异 | 总 token／维护成本上升，命令无法执行 | 按任务依赖拆分、复用现有入口；执行前核验工具，按端到端成本评测 |
