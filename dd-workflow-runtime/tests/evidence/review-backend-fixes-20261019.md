## 复现与根因

1. 改绑工具在临时 agents 副本执行 Codex 换模型：错误修改 worker 与 reviewer、未同步 worker 产物；新增 YAML 引号又不被现有绑定读取器去除，校验失败且源配置已经改变。复现测试还确认相同旧模型名出现在其他宿主时会被全局替换误改。
2. `readonly_exception` 的绝对路径即使位于仓库内也被接受；旧 containment 检查只约束解析后的目标，没有验证输入必须是仓库相对路径。
3. transport 的 Codex 只读豁免段位于 OpenCode 小节，OpenCode 套餐与 adapter 段又位于 Codex 小节；同一小节内出现应重采与豁免重采的混杂指令。

新增的首轮 6 项改绑测试中 4 项失败，仓库内绝对路径测试失败；修复后转绿。另以新增失败测试确认待合入改动移除了通用 sandbox 一致性检查，随后恢复原保护目的，保留新的 Codex 只读要素检查。

## 修复

- 改绑按宿主、角色定位；Codex 只改 reviewer 与 advisory，OpenCode 保留双角色同模型。原生产默认模型与推理强度不改。
- 产物路径由共享绑定声明决定；任何目标缺失均在写入前失败。候选在临时副本运行两个既有校验器，通过后才写源配置；发布期间 I/O 失败回滚已写文件，检测到并发修改时保留并报告。
- 拒绝绝对路径、`..` 与反斜杠路径，继续核对解析后的仓库边界和文件存在性。
- 分离两个后端的小节；共用读取方式只有一处，重采说明明确区分豁免期间与恢复机械只读之后。
- 原有只读豁免、轮前轮后基线检查、历史探测材料随本次交付保留；不将旧只读豁免回执解释为新协作通道的关闭证据。
