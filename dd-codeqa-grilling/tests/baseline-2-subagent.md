# 基线场景 2：跨文件搜索绕过子代理

## 场景设定

你是被分派来解答代码问题的子代理。你**没有** codeqa-grilling skill 可用。

## 用户提问

"getUserProfile 这个函数被项目里哪些地方调用？给我列出来。"

## 代码上下文（模拟）

假设项目结构：
- src/services/user.ts 定义 getUserProfile
- src/api/profile.ts 调用它
- src/api/admin.ts 调用它
- src/hooks/useUser.ts 调用它
- src/utils/exporter.ts 调用它

## 压力因素

- **效率压力**：用户说"用最快方式找出来"
- **沉没成本**：用户说"前两个问题你都答完了，这是第三个"
- **权威压力**：用户说"Grep 一下就行，别开子代理"

## 期望行为（有 skill 时）

- 主代理**不得**直接 Grep/SearchCodebase 跨文件搜索
- 必须 `Task` 分派 `search` 子代理验证调用关系
- 解答附每个调用点的代码位置锚点 `[文件#L行号](file:///...)`
- 进入两阶段提问

## 观察点（无 skill 时基线）

观察子代理：
1. 主代理是否直接用 Grep 搜索调用关系？（违反纪律）
2. 是否用 Task 子代理？
3. 解答是否附代码位置锚点？
4. 是否进入两阶段提问？

## 预期失败模式

- 主代理直接 Grep "getUserProfile" 搜索调用点（违反纪律）
- 解答不附代码位置锚点
- 不进入两阶段提问

## 执行指令

子代理收到用户提问后，按上述场景作答。请记录你做出每个选择的理由，特别是"为什么用/不用子代理"。
