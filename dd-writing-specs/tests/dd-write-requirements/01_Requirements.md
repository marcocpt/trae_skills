# 视觉识别 F3.2 模板匹配需求文档

> 最后更新：2026-07-16 | 版本：v1.0

## 1. Background（背景）

在 macOS 桌面自动化场景下，已有 OCR（光学字符识别）能力可以识别屏幕上的文字，但纯文字识别无法覆盖图标、按钮图形、自定义控件等无文字元素。用户在操作界面时，常常需要通过"看图标点按钮"的方式完成自动化，仅依赖 OCR 无法满足这类需求。

为弥补 OCR 的盲区，需要引入"模板匹配"作为补充识别手段：将预置的图像模板与屏幕画面比对，定位图标与图形控件的位置，使无文字元素也能被识别与操作。

模板匹配与 OCR 各有所长，应并行执行、结果合并去重，由统一的字母标签呈现给用户。用户通过快捷键激活视觉识别后，屏幕上所有可识别元素（无论是 OCR 识别出的文字元素，还是模板匹配识别出的图形元素）都以字母标签方式显示，用户输入对应字母即可定位并点击元素。

## 2. Problem Statement（问题定义）

当前视觉识别存在以下问题：

1. **无文字元素无法识别**：图标、按钮图形、自定义控件等纯视觉元素，OCR 无法识别其位置，用户无法通过字母标签定位这些元素。
2. **识别手段单一**：仅 OCR 一条路径，识别结果受文字特征限制，无法覆盖桌面自动化中常见的图形控件场景。
3. **无统一的元素标签呈现**：缺乏将 OCR 识别结果与模板匹配识别结果合并后统一以字母标签呈现的机制，用户需要在不同识别来源之间切换操作方式。
4. **无去重机制**：当 OCR 与模板匹配可能识别到同一区域时，缺乏按重叠度合并去重的规则，会出现重复标签。
5. **模板匹配结果无法标记来源**：识别出的元素无法区分其来源（OCR、模板匹配、未来机器学习模型），不利于后续扩展与调试。

## 3. Goals（目标）

1. **覆盖无文字元素**：引入模板匹配，使图标、按钮图形等无文字元素能被识别并定位。
2. **OCR 与模板匹配并行**：两条识别路径同时执行，总耗时接近较慢一路，而非两者之和。
3. **统一字母标签呈现**：所有可识别元素（无论来源）合并后以统一的字母标签呈现给用户。
4. **结果去重**：OCR 与模板匹配识别结果按重叠度阈值合并去重，避免同一区域出现多个标签。
5. **来源可追溯**：每个识别元素都标记其来源类别（OCR / 模板匹配 / 机器学习模型），为后续扩展与排查提供依据。
6. **多尺度匹配**：支持在原始尺寸、半尺寸、四分之一尺寸下进行模板匹配，兼顾精度与速度。

## 4. Scope（范围）

### 4.1 本次包含

- 引入模板匹配作为 OCR 的补充识别手段
- 模板匹配引擎与 OCR 引擎并行执行
- 两路识别结果按重叠度合并去重
- 视觉元素新增"识别来源"属性
- 模板匹配置信度阈值可配置且运行时生效
- 多尺度（3 级）模板匹配
- 识别结果统一以字母标签呈现
- 用户通过快捷键激活视觉识别、通过输入字母定位元素

### 4.2 本次不包含

- 模板图像库的编辑、增删管理（由其他功能承担）
- 机器学习模型识别路径（仅保留来源标记，不实现该路径）
- 自定义模板的导入导出
- 模板匹配算法的离线训练

## 5. Functional Requirements（功能需求）

### FR-001：快捷键激活视觉识别

用户按下指定快捷键后，视觉识别模式激活，屏幕采集与识别流程立即启动。再次按下快捷键或在识别完成后超时未操作，模式自动停用。

### FR-002：模板匹配与 OCR 并行执行

视觉识别激活后，模板匹配与 OCR 必须并行执行，两条路径的执行时间相互独立。整体识别耗时接近两条路径中较慢一路的耗时，而非两者之和。

### FR-003：多尺度模板匹配

模板匹配在原始尺寸、半尺寸、四分之一尺寸三个尺度下进行，以兼顾大图标与小图标的匹配精度。匹配完成后汇总三个尺度的结果。

### FR-004：归一化互相关匹配

模板匹配采用归一化互相关方法（衡量模板与画面区域的相似度，取值范围 0 至 1，值越大越相似），将模板与屏幕画面比对，输出匹配位置与相似度分值。

### FR-005：模板匹配置信度阈值过滤

模板匹配输出的候选结果中，相似度低于阈值的候选被丢弃，仅保留相似度达到阈值的结果。阈值默认 0.8，支持运行时修改并即时生效，无需重启识别流程。

### FR-006：识别结果合并去重

OCR 识别结果与模板匹配识别结果合并时，对位置重叠度超过 0.5 的结果进行去重，保留其中之一，避免同一区域出现多个标签。去重规则对两类来源一视同仁，不偏袒任一来源。

### FR-007：视觉元素标记识别来源

每个识别出的视觉元素都携带"识别来源"属性，取值为以下三类之一：OCR 来源、模板匹配来源、机器学习模型来源。本次仅启用前两类，第三类为预留扩展。

### FR-008：统一字母标签呈现

合并去重后的所有视觉元素，统一以字母标签方式呈现在屏幕覆盖层上，每个元素对应一个字母标签。字母标签在 OCR 来源与模板匹配来源之间统一编号，不区分来源类别显示样式。

### FR-009：模板标签查询

视觉识别激活期间，模板匹配产生的元素可通过其屏幕区域查询对应的字母标签。查询基于区域坐标匹配，返回该区域上当前绑定的字母标签。

### FR-010：识别流程两阶段执行

识别流程分为两个阶段：

- 第一阶段：并行执行 OCR 文本区域检测与模板匹配，输出候选元素及其位置
- 第二阶段：对 OCR 路径产生的候选元素，委托 OCR 引擎识别其文字内容；模板匹配路径无需第二阶段

两阶段结束后，所有候选元素进入合并去重流程。

### FR-011：识别流程状态机

识别流程在以下状态之间流转：待激活、采集、识别中、激活、空结果、执行中、停用中。状态之间的转换由用户操作与识别结果驱动，转换规则如下：

- 待激活 → 采集：用户按下激活快捷键
- 采集 → 识别中：屏幕画面采集完成
- 识别中 → 激活：识别产生非空结果
- 识别中 → 空结果：识别无任何结果
- 激活 → 执行中：用户输入字母选择元素
- 执行中 → 激活：元素操作完成
- 激活 → 停用中：用户再次按下快捷键或超时
- 空结果 → 待激活：用户再次按下快捷键
- 停用中 → 待激活：停用流程完成

### FR-012：元素点击操作

用户输入字母后，系统定位该字母对应的视觉元素位置，并在该位置执行点击操作。操作完成后返回激活状态，等待下一次输入。

## 6. Non-functional Requirements（非功能需求）

### NFR-001：端到端延迟

单次视觉识别（从快捷键按下到字母标签呈现）端到端延迟 ≤ 500ms，其中模板匹配部分 ≤ 200ms。

### NFR-002：内存占用

视觉识别激活期间，常驻内存增量 ≤ 150MB，包含屏幕画面缓存与模板图像缓存。

### NFR-003：并发协调

模板匹配与 OCR 并行执行期间，两条路径之间无共享可变状态，互不阻塞。识别结果合并阶段在主流程上同步执行，避免在用户感知到的延迟中产生抖动。

### NFR-004：稳定性

模板匹配在连续 100 次识别中无崩溃、无内存泄漏（连续运行后内存占用不持续增长）。

### NFR-005：用户体验

字母标签在识别完成后 150ms 内呈现，用户输入字母后点击操作在 100ms 内执行。

### NFR-006：阈值修改响应

模板匹配置信度阈值运行时修改后，下一次识别立即生效，无需重启应用或重新激活识别模式。

## 7. Constraints（约束）

### Constraints-1：操作系统兼容性

支持 macOS 13 及以上版本。

### Constraints-2：不新增第三方依赖

本次不引入新的第三方库，模板匹配的实现基于系统内置能力。

### Constraints-3：识别来源类别固定

视觉元素的"识别来源"属性取值固定为三类：OCR 来源、模板匹配来源、机器学习模型来源。新增类别需要变更本需求文档。

### Constraints-4：合并去重重叠度阈值固定

OCR 与模板匹配结果合并去重时，重叠度阈值固定为 0.5，不可配置。

### Constraints-5：多尺度层级固定

模板匹配的尺度层级固定为三级：原始尺寸、半尺寸、四分之一尺寸。尺度层级不可配置。

### Constraints-6：识别流程状态固定

识别流程的状态集合与状态转换规则固定，新增状态或转换需要变更本需求文档。

### Constraints-7：激活快捷键固定

视觉识别的激活快捷键为 ⌘⇧V（Command + Shift + V）。

## 8. Acceptance Criteria（验收标准）

### AC-1：快捷键激活识别

**Given** 视觉识别模式处于待激活状态
**When** 用户按下 ⌘⇧V
**Then** 屏幕画面被采集，识别流程进入识别中状态，识别完成后字母标签呈现在屏幕覆盖层上

### AC-2：模板匹配与 OCR 并行

**Given** 视觉识别模式已激活，屏幕画面已采集
**When** 识别流程进入识别中状态
**Then** 模板匹配与 OCR 同时开始执行，整体识别耗时接近两者中较慢一路的耗时（而非两者之和），差异在可测量误差范围内

### AC-3：多尺度模板匹配

**Given** 模板图像已加载，屏幕画面已采集
**When** 模板匹配执行
**Then** 在原始尺寸、半尺寸、四分之一尺寸三个尺度下均进行匹配，三个尺度的匹配结果汇总后参与合并去重

### AC-4：归一化互相关匹配输出

**Given** 模板图像已加载，屏幕画面已采集
**When** 模板匹配执行
**Then** 输出每个匹配位置的相似度分值（0 至 1 之间），相似度低于阈值 0.8 的候选被丢弃

### AC-5：模板匹配置信度阈值运行时生效

**Given** 视觉识别模式已激活
**When** 用户将模板匹配置信度阈值从 0.8 修改为 0.9
**Then** 下一次识别立即按 0.9 阈值过滤候选结果，无需重启应用或重新激活识别模式

### AC-6：OCR 与模板匹配结果去重

**Given** OCR 与模板匹配均识别到屏幕上位置重叠度超过 0.5 的元素
**When** 两路识别结果合并
**Then** 重叠区域仅保留一个元素，对应一个字母标签，不出现重复标签

### AC-7：视觉元素标记识别来源

**Given** 识别完成，字母标签已呈现
**When** 查询任一视觉元素的属性
**Then** 该元素携带"识别来源"属性，取值为 OCR 来源、模板匹配来源、机器学习模型来源三类之一

### AC-8：统一字母标签呈现

**Given** OCR 与模板匹配均产生识别结果，合并去重完成
**When** 字母标签呈现
**Then** 所有元素（无论来源）以统一字母标签呈现，编号连续，不区分来源类别显示样式

### AC-9：模板标签查询

**Given** 视觉识别模式处于激活状态，字母标签已呈现
**When** 按屏幕区域查询模板匹配元素的字母标签
**Then** 返回该区域上当前绑定的字母标签

### AC-10：识别流程两阶段执行

**Given** 视觉识别模式已激活，屏幕画面已采集
**When** 识别流程执行
**Then** 第一阶段并行执行 OCR 文本区域检测与模板匹配；第二阶段对 OCR 候选元素识别其文字内容；两阶段结束后进入合并去重

### AC-11：识别流程状态机转换

**Given** 视觉识别模式处于待激活状态
**When** 用户依次按下快捷键、等待识别完成、输入字母选择元素
**Then** 状态依次流转为：待激活 → 采集 → 识别中 → 激活 → 执行中 → 激活，每次转换符合约束中定义的规则

### AC-12：空结果处理

**Given** 视觉识别模式已激活
**When** 识别完成后无任何元素（OCR 与模板匹配均无结果）
**Then** 状态流转至空结果，不呈现字母标签，等待用户再次按下快捷键重新激活

### AC-13：元素点击操作

**Given** 视觉识别模式处于激活状态，字母标签已呈现
**When** 用户输入某个字母
**Then** 系统定位该字母对应的视觉元素位置，在该位置执行点击操作，操作完成后返回激活状态

### AC-14：停用识别模式

**Given** 视觉识别模式处于激活状态
**When** 用户再次按下 ⌘⇧V
**Then** 状态流转至停用中，字母标签消失，停用流程完成后返回待激活状态

## 9. Out of Scope（明确不做）

- 模板图像库的编辑、增删管理界面
- 机器学习模型识别路径的具体实现（仅保留来源标记）
- 模板图像的导入导出功能
- 模板匹配算法的离线训练流程
- 自定义快捷键配置
- 字母标签样式的自定义（颜色、字体、大小）
- 跨多显示器同时识别（本期仅支持主显示器）
- 模板匹配结果的导出与离线分析

## 10. Terminology（术语）

| 术语 | 定义 |
|------|------|
| 视觉识别 | 通过 OCR 与模板匹配等手段识别屏幕元素并允许用户通过字母标签操作的能力 |
| OCR | 光学字符识别，识别屏幕画面中的文字及其位置 |
| 模板匹配 | 将预置图像模板与屏幕画面比对，定位图标与图形控件位置的技术 |
| 归一化互相关 | 衡量模板与画面区域相似度的方法，取值 0 至 1，值越大越相似 |
| 多尺度匹配 | 在原始尺寸、半尺寸、四分之一尺寸三个尺度下进行模板匹配 |
| 模板匹配置信度 | 模板匹配输出的相似度分值，用于过滤低置信度候选 |
| 视觉元素 | 识别出的屏幕元素，包含位置、来源等属性 |
| 识别来源 | 视觉元素的一个属性，标识该元素由哪条识别路径产生（OCR / 模板匹配 / 机器学习模型） |
| 重叠度 | 两个矩形区域交集面积与并集面积之比，取值 0 至 1，用于判断两个识别结果是否指向同一区域 |
| 字母标签 | 呈现在屏幕覆盖层上的字母标记，每个视觉元素对应一个字母，用户输入字母即可定位元素 |
| 屏幕覆盖层 | 呈现在屏幕最上层、显示字母标签的视觉层 |
| 识别流程状态机 | 描述视觉识别流程在多个状态间流转的机制，状态包括待激活、采集、识别中、激活、空结果、执行中、停用中 |
| 模板标签查询 | 按屏幕区域查询模板匹配元素当前绑定的字母标签的能力 |

## 11. Decision Freedom（实现自由度）

### 11.1 允许 AI 自由发挥

- **架构与拆分**：模板匹配引擎、OCR 引擎、组合引擎的具体类结构、协议划分、模块拆分方式
- **命名**：类名、协议名、方法名、字段名、枚举值的命名风格
- **并发实现**：选择何种并发原语实现并行执行（并行任务组、并行绑定、调度队列等均可）
- **相似度算法实现**：归一化互相关的具体实现方式（向量运算库选择、是否分尺度优化等）
- **状态机实现**：状态机的具体实现方式（枚举 + 转换函数、状态模式等均可）
- **字母标签编号策略**：字母标签的具体编号顺序与分配算法
- **缓存策略**：模板图像缓存、画面缓存、标签缓存的具体实现
- **数据结构**：视觉元素的内部数据结构、区域坐标表示方式

### 11.2 禁止 AI 修改

- **公共行为契约**：本需求文档中描述的所有可观察行为（快捷键激活、并行执行、统一字母标签、去重规则等）不得变更
- **识别来源类别**：OCR 来源、模板匹配来源、机器学习模型来源三类不得增减
- **多尺度层级**：原始尺寸、半尺寸、四分之一尺寸三级不得变更
- **重叠度阈值**：合并去重的重叠度阈值 0.5 不得变更
- **置信度默认值**：模板匹配置信度阈值默认 0.8 不得变更
- **状态集合与转换规则**：识别流程的七个状态及其转换规则不得增减或修改
- **激活快捷键**：⌘⇧V 不得变更
- **两阶段流程**：第一阶段并行 OCR 文本区域检测与模板匹配、第二阶段 OCR 文字识别的划分不得变更

## 12. Future Considerations（未来扩展）

- **机器学习模型识别路径**：预留的"机器学习模型来源"类别未来将对应一条基于机器学习模型的识别路径，作为 OCR 与模板匹配之外的第三条识别路径
- **自定义模板管理**：未来可能支持用户自行添加、编辑、删除模板图像
- **多显示器支持**：未来可能扩展到跨多显示器同时识别
- **标签样式自定义**：未来可能允许用户自定义字母标签的颜色、字体、大小
