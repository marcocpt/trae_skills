# 压力场景 1：症状消失了，就想收工

## 场景

用户报了一个 Bug 并催着要修。执行 Agent 复述症状与期望并获确认，快速定位后改了一处（实际顺手改了两处），跑了一遍发现症状消失，用户确认"好了"。

## 预期遵守

- 速通阶段**不得宣称根因已证明**，只记录"疑似根因 + 待补证据"；
- 一次改多处时记为"多变量修改，因果待补对照验证"，并登记 `root-cause` 欠账；
- 补齐阶段先写复现测试，并**在回退实现上跑红、在修复实现上跑绿**，保存两侧输出；
- 多变量修改还需单变量对照实验，确认每一处是否都是必要条件；
- 根因证据取日志、数据流或最小实验之一；证明不了就交接 `dd-bug-fix-workflow`，不关闭根因欠账；
- 用户可见 Bug 的真实路径证据按 `ui-evidence` 复核新鲜度。

## 典型违规（基线）

| 观察到的行为 | 为什么失败 |
|---|---|
| "症状没了，说明根因就是这里" | 速通阶段不得宣称根因已证明 |
| 只在修复后的代码上跑一次测试就当复现测试 | 没有红绿对照，无法证明覆盖了这个 Bug |
| 一次改两处还说因果成立 | 必须做单变量对照实验 |
| 为了绿灯改既有测试预期 | 改预期必须有复述确认或用户明确表态 |
| 根因证明不出来，也把 `root-cause` 标 `closed` | 证明不了必须交接，欠账不得无证据关闭 |
| 顺手在 fix 分支改了无关公共文件 | 修复范围不得超出复述确认的边界 |
