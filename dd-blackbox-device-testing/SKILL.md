# 不改设备的黑盒测试用例

把已交付设备视为固定黑盒。先找能操作的外部输入与能采集的输出，再决定能够证明的要求；间接符合不能扩大成内部实现已验证。

## 边界

- 不烧录、打补丁、加日志/测试固件、加GPIO打点、开壳焊线、改电路、探内部节点；不用调试器、断点、RAM/寄存器访问、烧录器直写EEPROM/ULPEE。
- 可使用现有按键、已交付的正常业务接口、外部LF/RF、电场/磁场/温度及接收仪器；电源夹具只接现成电池连接或指定外部触点，需拆改才能接入时不可执行。
- 正常业务学习引起的业务数据变化须经设备既有、已确认支持的流程；不得用任意写页、恢复镜像、工程置数冒充学习。没有接口就登记缺口，不要求给设备新增接口。
- DUT 禁改不等于辅助上位机禁改：可在授权范围开发辅助设备/仿真基站的激励、采集、判定与记录；能力先核验，不擅自改其他项目，不把台架发包日志当成实际到达设备的证明。
- 仅为本次任务明确禁止侵入验证的对象应用上述限制；不要把此项目约束扩成所有项目永远禁止调试。

## 编写方法

1. 逐例找出输入如何产生、输出在哪里测量、预期从哪里独立取得、如何判激励和捕获有效。
2. 优先改为正常操作加空口原帧、外部RF包络/IQ、非接触LF场测量、电源端电流；身份/测试密钥从可信交付记录或既有正常接口取得，不能靠猜测或拟合被测输出生成Oracle。
3. 给出实际条件和反证：已测行为、成立假设、未证明部分；区分“本输入下输出正确”与“内部常量/全密文/硬件调用正确”。未知测试密钥时仍可测格式/重复性/互操作，但密码正确性保留未验证。
4. 无可达激励时，换已有且来源可靠的样品、正常操作或外部协议中断；不能偷偷置数或伪造故障。没有近回绕样品，就不声称普通递增验证了回绕。
5. 保留原需求、编号、优先级与覆盖缺口，不把要求删掉或标不适用。可执行替代场景明确命名为部分/间接覆盖；不可测内部断言保留NOT-READY/NOT-RUN及本阶段原因，不写成“等开发调试钩子”。
6. 同步用例、方案、追溯、缺口、台架能力、看板和交接入口。纯宿主参考自检保持L1，不计入设备通过。

## 上位机与精简用例

- 先区分现有、待开发及人工能力；上位机能承担的激励、采集、解析、计算、判定和日志优先由上位机完成。优先交付已有能力支撑的用例，待开发能力保留接口与阻塞原因，不以全部自动化完成作为当前交付前提。
- 优先复用现有设备；每例只增加激励或观测确实必需的设备，不把示波器等仪器列为所有用例的通用前置。
- 公共连接、收发、身份读取、判定和日志封装为可复用接口；每例一个独立测试函数。尊重用户指定的分层与开发顺序，已有应用层接口时测试函数不绕过它直接操作硬件；不把某项目的名称、参数或层次顺序固化为通用规则。
- 自动判定同时输出实际值、期望值、结论及证据定位。RECORD 仅表示记录，不算通过；缺门限、缺证据或能力未就绪时不得自动报 PASS，状态沿用项目枚举。
- 人工按键等激励可配自动采集判定，须标清人工环节。不能自动判断时由人工示波器等外部测量接续，程序提示、记录并保持待人工判定；仅记录波形或完成提示不能自动报 PASS，人工结论须有测量值、依据与证据。
- 公共设备、前置、步骤、依据及证据格式集中定义并引用；每例只写差异。精简模板：`原编号/需求/优先级 → 测试函数 → 公共配置引用与本例例外 → 关键操作/观测 → 期望与判据 → 自动/人工分工 → 状态/证据`。相同字段不逐例复制，独有前置、异常路径、判据和覆盖边界不得省略。

## 必须挡住的误判

- 4B Response核对只能覆盖对应可见输出及组合算法路径，不能证明完整16B密文、特定内部常量或实际使用硬件AES。
- LF结束到RF开始是外部响应延时；没有独立的包含关系依据不能替代ADC耗时。即使有保守上界证明，上界超限也不自动证明内部耗时超限。
- 电流段/无RF可用于外部状态佐证；必须有对照和有效性依据，不能把平均电流低于门限循环当成已休眠证明，或以电流尖峰证明某次ADC转换。
- 改台架回包/抑制确认、断电/阻断链路是相应外部故障，不是已命中设备EEPROM某页某一bit；按真实可观测故障命名。
- 重复RF字段可说明一致性，缺独立ID/密钥/物理标定时不提升为绝对正确。
- 缺证据、没有接口、捕获不完整均不是设备FAIL，也不是PASS；报告未执行/证据不足及尚未覆盖的要求。不要为了通过率缩小分母。

## 质量门

检查每例能通过正文或有效公共引用还原目的、前置、操作、期望依据、判据和证据；不强制重复字段或长段落。保留项目必需信息、状态枚举与用户裁决，写清外部方法和覆盖边界；不自定门限，不宣称上板或外部复审已完成。压力验证记录保存到任务指定位置；额外审查仅按用户当前要求执行。
