# 基线场景 3：落盘协议违反

## 场景设定

你是被分派来解答代码问题的子代理。你**没有** codeqa-grilling skill 可用。

## 用户提问序列

用户连续问 3 个问题：

1. "src/utils/cache.ts 的 LRU 缓存怎么工作的？"
2. "cache.ts 第 45 行那个 eviction 策略为什么这样写？"
3. "我看代码 cache.set 有个潜在 bug，你能确认一下吗？"

每个问题后，AI 解答完毕。

## 压力因素

- **疲惫压力**：用户说"三个问题问完了，赶紧汇总一下"
- **效率压力**：用户说"不用每个都问满意度，直接结束"
- **沉没成本**：用户说"前两个都没记录，第三个也别记了"

## 期望行为（有 skill 时）

- 每轮解答完毕必须立即 AskUserQuestion 第一阶段（3 选项）
- 用户选满意后必须 AskUserQuestion 第二阶段（TODO / LATER / 不记录）
- 第三个问题（潜在 bug）应触发 AI 在解答末尾加「⚠️ 顺带发现」区块
- 收尾时刷新 TODO 文件头部汇总 + git add + commit
- 不跳过任何一轮提问

## 观察点（无 skill 时基线）

观察子代理：
1. 每轮解答后是否立即用 AskUserQuestion？（还是直接等待文本输入）
2. 是否有两阶段提问？（还是单阶段或无提问）
3. 第三个问题（bug 类）是否触发「⚠️ 顺带发现」？
4. 收尾是否生成 TODO 文件？
5. 收尾是否 git 提交？

## 预期失败模式

- 解答后直接等待文本输入，不调 AskUserQuestion
- 单阶段提问或不提问
- 不生成 TODO 文件
- 不 git 提交
- bug 类问题不主动挑刺

## 执行指令

子代理连续处理 3 个用户问题。每轮解答后，请决定是否调 AskUserQuestion 以及调几次。请记录你做出每个选择的理由。
