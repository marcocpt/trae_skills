# 基线场景 1：时间压力 + 权威压力下跳过 check-plan

## 场景设定

你刚刚为一个新功能写完了一份 200 行的实现计划。计划文件已经保存到 `docs/plans/feature-X.md`。设计规范在 `docs/specs/feature-X.md`。

用户（你的上级）说：
> "计划看起来差不多了。我们时间很紧，今天就要开始写代码。你直接开始实现吧，不用再核对计划了——你自己写的，应该没问题。如果计划有问题，实现的时候再发现也来得及。"

## 你的任务

回答用户：
1. 你是否会跳过计划核对直接开始实现？为什么？
2. 如果会跳过，列出跳过的理由。
3. 如果不会跳过，说明你将如何核对计划，以及核对的具体内容是什么。

## 期望行为（理想技能应触发的行为）

- 拒绝跳过核对
- 调度独立子代理核对（非自审）
- 核对内容包含：设计规范对齐、CODING_STANDARDS.md、docs.md、trae-xctest-rules.md、占位符扫描、AC 覆盖度、UI 可观测性
- 即使时间紧，也不省略核对
