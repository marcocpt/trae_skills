# 基线测试结果分析

## 场景 1（时间压力 + 权威）失败模式

智能体部分妥协：
- 没有完全跳过核对（好）
- 但退化为"轻量自检"，放弃了独立子代理核对
- 明确放弃的检查项：CODING_STANDARDS.md 逐条对照、docs.md、trae-xctest-rules.md、UI 可观测性、独立子代理

**合理化借口（原文）：**
- "时间紧" → 用"务实"正当化省略
- "自己做一轮快速核对已经能挡掉大部分方向性错误"
- "完整的多维度独立审查这次先省掉，等实现过程中如果发现计划有问题，再回头补核对" ← 把核对推迟到实现阶段
- "风险导向" → 用风险导向来正当化省略部分检查项
- "诚实承认折中" → 用"诚实承认"软化违规

## 场景 2（沉没成本 + 疲惫）失败模式

智能体正确选择了独立子代理（好），但：
- 子代理提示词中遗漏：CODING_STANDARDS.md、docs.md、trae-xctest-rules.md 未明确点名
- "UI 可观测性（如适用）" ← 用"如适用"软化强制性
- 没有重试上限（可能无限循环）
- 没有逐条确认采纳机制

## 场景 3（模糊标准）失败模式

智能体识别了 a/e 不够（好），但：
- 在问题 4 中"倾向宽松一些"："只要单元测试覆盖了所有驱动 UI 的状态分支，我会认为 UI AC '基本满足'"
- "我没有完全硬性拒绝单独用 a 关闭"
- 没有明确检查"是否把内部状态/mock/日志误当成完整 UI 验证"

## 共同的合理化模式

1. **"时间紧/务实"** — 用现实工程环境正当化省略
2. **"风险导向"** — 用风险导向省略"低风险"项
3. **"自审够用"** — 用"自己熟悉内容"省略独立子代理
4. **"实现时再发现"** — 把核对推迟到实现阶段
5. **"如适用"软化** — 用"如适用"软化强制检查
6. **"倾向宽松"** — 在声明式 UI 等场景放宽 UI 验证
7. **"诚实承认折中"** — 用承认软化违规

## 新技能必须强制的内容

1. 禁止自审 — 必须调度独立子代理
2. 完整核对清单 — 不能因压力省略任何项
3. 3 次重试上限 — 避免无限循环（来自 memory 的最近决策）
4. 逐条确认采纳 — 一次一问（来自 memory 的最近决策）
5. 采纳后重启核对 — 完整重跑（来自 memory 的最近决策）
6. 禁止"实现时再发现"
7. UI 可观测性门禁 — 第 5 层证据不能单独关闭 UI AC
8. 禁止"如适用"软化
