# 创建日志 (CREATION LOG)

plan-and-code-verification

## 来源
整合 `writing-plans` + `check-plan` + `check-code` 三个子技能，参考 `feature-development-workflow` 的步骤 3-4 结构。

## TDD 流程记录

### 红色阶段（基线测试）

创建 3 个基线压力场景，并行调度子代理运行（无技能情况下）：

**场景 1（时间压力 + 权威）：**
- 智能体部分妥协：未完全跳过核对，但退化为"轻量自检"
- 明确放弃检查项：CODING_STANDARDS、docs.md、trae-xctest-rules、UI 可观测性、独立子代理
- 合理化借口：用"务实"、"风险导向"、"诚实承认折中"正当化省略

**场景 2（沉没成本 + 疲惫）：**
- 智能体正确选择了独立子代理
- 但子代理提示词中遗漏 CODING_STANDARDS、docs.md、trae-xctest-rules 未明确点名
- 用"如适用"软化 UI 可观测性检查
- 缺少重试上限和逐条确认机制

**场景 3（模糊标准）：**
- 智能体识别 a/e 不够（好）
- 但在问题 4 中"倾向宽松"："只要单元测试覆盖了所有驱动 UI 的状态分支，我会认为 UI AC '基本满足'"
- 没有明确检查"是否把内部状态/mock/日志误当成完整 UI 验证"

### 绿色阶段（编写技能）

编写 `SKILL.md`，针对基线失败设计：

1. **禁止自审铁律** — 强制独立子代理核对
2. **完整核对清单** — 12 项检查表（计划）+ 8 项检查表（代码）
3. **3 次重试上限** — 避免无限循环（来自 memory 中 grilling skill 的最近决策）
4. **逐条确认采纳** — 一次一问，10 条问 10 次（来自 memory 中 grilling skill 的最近决策）
5. **采纳后完整重跑** — 不增量核对（来自 memory 中 grilling skill 的最近决策）
6. **UI 可观测性门禁** — 5 层证据分层，第 5 层不能单独关闭 UI AC
7. **合理化借口表** — 13 条借口对照
8. **红线列表** — 11 条违规行为

### 绿色阶段验证（带技能重跑）

并行调度 3 个子代理，**严格遵循技能规则**重跑场景：

**场景 1 验证：** ✅ 通过
- 拒绝跳过核对
- 拒绝自审，调度独立子代理
- 列出完整 12 项核对检查表
- 引用合理化借口表逐条驳回上级理由

**场景 2 验证：** ✅ 通过
- 选择独立子代理（明确拒绝自审）
- 提示词包含完整核对检查表，明确点名 CODING_STANDARDS、docs.md、trae-xctest-rules
- 拒绝"如适用"软化
- 包含 3 次重试上限 + 逐条确认 + 完整重跑

**场景 3 验证：** ✅ 通过
- 严格按 5 层证据分层回答
- 明确 a 单独绝不足够
- 拒绝标记"只有单元测试的 UI AC"为已完成
- 正确标记为"未完成 UI 验证"
- 对 3 条 UI AC 逐条核对（不笼统判断）

### 重构阶段

1. **收紧 description**：移除 workflow summary 痕迹（"need to write plan + verify plan"），改为纯触发条件
2. **明确自检定位**：自检是补充而非替代，添加显式声明防止误读
3. **扩展合理化借口表**：新增 2 条借口
   - "自检通过就不用独立子代理核对了"
   - "子代理提示词简单写就行"

## 与原技能的关系

- **writing-plans**：本技能整合了其计划结构、任务粒度、禁止占位符等核心内容
- **check-plan**：本技能将其从一句话扩展为完整的 12 项核对检查表 + 处理流程
- **check-code**：本技能将其从一句话扩展为完整的 8 项核对检查表 + UI 可观测性门禁
- **feature-development-workflow**：本技能是其步骤 3-4 中"核对"部分的独立化抽取，可在其内作为子技能使用，也可单独使用

原三个技能保留不删除，本技能是它们的整合增强版。
